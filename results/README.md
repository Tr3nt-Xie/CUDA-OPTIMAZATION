# Experiment Results

```text
raw/<member>-<YYYYMMDD-HHMM>/
  *.csv             # measurements.csv or one CSV per configuration; shared columns in configs/benchmark.json
  environment.txt   # generated by scripts/collect_env.sh
summary/            # means and speedups generated by the summary scripts
figures/            # figures generated from real data
```

Every formal run gets a new directory and never overwrites existing results; failures or missing measurements are explained in the report, and the fastest run is never cherry-picked. CSVs may be split and named to suit the actual run, but the input identity and its mapping to results must be kept, and summaries never mix different inputs.

In this batch, the end-to-end speedups at N=256/512/1024/2048 are about 37.80/98.44/461.82/1388.36×. Among the small sizes, the end-to-end GPU time is still longer at N=32, only about 1.25× faster at N=64, and about 8.73× faster at N=128. These are observations for this hardware, implementation, and warm-up/timing method; the three measurements were not used for significance testing. `GPU end_to_end - compute` includes allocation, copies, synchronization, and cleanup, and must not be read as a separately measured transfer time.

Each batch's `commands.jsonl` records every command with start/end times and exit codes, and `source-snapshot.tar.gz` stores the source at that time. Two `._` metadata files carried over from the initial Mac transfer are also recorded as-is in the snapshot; they are not compiled, were later removed from the remote worktree, and the historical record is not rewritten. Plotting scripts and dependencies added later are not part of the timed code and are traced separately by `provenance.json` in the figure directories.

To collect again on an idle lab machine, use a new run ID and never overwrite existing data:

```sh

export NVCCFLAGS='-O2 -std=c++14 -arch=sm_75'
python scripts/run_part_a_matrix.py --run-id A-NEW-matrix --context 'Shared AWS T4 host'
python scripts/run_part81_cpu.py --run-id A-NEW-conv --context 'CPU baseline on shared AWS T4 host'
python scripts/plot_part_a.py A-NEW-matrix
```

## How the Part 8.1 convolution CSVs are organized

In `part81-cpu-aws`, each raw CSV file name contains the image, M, K, and filter, while the content keeps the team's shared columns. Each configuration has 3 runs × 2 timing_scopes, 6 rows in total. Image loading, reference computation, validation, and PNG generation are not counted in CPU compute; in the current CPU implementation, end_to_end equals compute. The independent checks are done on the unclipped float32 outputs.

Earlier local convolution validation batches run on a Mac have been removed from the repository (they can be found in commit `a2f7c1c`): they were not run on the AWS machine, so speedups against GPU data cannot be computed from them; they are superseded by the same-host AWS batch above.
